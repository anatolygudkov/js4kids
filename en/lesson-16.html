The game on the internet

Until now the game has only lived in the code folder on your Raspberry Pi. Today we'll put it on the internet, and anyone with the link will be able to play it: friends, grandparents, classmates. A free service called GitHub Pages will help us.

In this lesson you will:
  • prepare an index.html file for publishing;
  • create a repository on the GitHub website together with a grown-up;
  • upload the game there and switch on GitHub Pages;
  • get a link to your game;
  • think up ways to improve the game further.

👨‍👩‍👧 For grown-ups

GitHub's rules only allow people aged 13 and over to have their own account. So use a grown-up's account (your own, or one created for this with your email) and go through the lesson together with your child. You'll need internet access.

No git or terminal is needed: the file is uploaded through the website with a button. If GitHub's interface has changed slightly by now, look for buttons with the same names.

The published game will be visible to everyone. Check that it contains no personal information: surname, address, school.

What GitHub is

GitHub is a website where programmers from all over the world keep their programs. Each program lives in its own repository ("repo" for short). It's like a folder on the internet.

GitHub Pages is a GitHub service that turns a repository into a real website with its own link. Our game is an HTML page, so it fits perfectly!

Step 1. Prepare the file

When a website is opened by its link, the first thing it looks for is a page called index.html (the "main page"). Let's make a copy of the game with that name:

  1. Open snake.html in Geany.
  2. File → Save As (Ctrl + Shift + S), folder code, name index.html. Click Save.
  3. Now Geany has index.html open. Close that tab: you'll keep changing your game in snake.html, and index.html is just the copy for the internet.

Look in the file manager: the code folder now has three files — test.html, snake.html and index.html.

Step 2. Create a repository

  1. Open github.com in the browser and Sign in. A grown-up does this.
  2. In the top right corner click + and choose New repository.
  3. In the Repository name box type snake.
  4. Check that Public is selected: GitHub Pages works for free with public repositories.
  5. Click the green Create repository button.

Step 3. Upload the game

  1. On the page of the new, empty repository, find the link uploading an existing file and click it. (If the repository isn't empty: the Add file → Upload files button.)
  2. Click choose your files, open your home folder → code and pick index.html. You can also just drag the file with the mouse from the file manager into the browser window.
  3. At the bottom of the page click the green Commit changes button.

Now index.html shows in the repository's list of files. Your code is on the internet!

Step 4. Switch on GitHub Pages

  1. At the top of the repository page click the Settings tab (the gear icon).
  2. In the menu on the left find and click Pages.
  3. In the Build and deployment section, in the Source box, choose Deploy from a branch.
  4. In the Branch box choose main, and leave the folder next to it as / (root). Click Save.
  5. Wait a minute or two and refresh the page (F5). At the top you'll see Your site is live at… and a Visit site button.

The address will look like this:

https://ACCOUNT-NAME.github.io/snake/

Click Visit site, and there it is — your Snake on the internet! 🎉🐍 Copy the link from the address bar and send it to your friends.

💡 The high score on the internet The game on the internet has its own high score, separate from the one in your code folder. And every player has their own on their computer too: localStorage lives in the browser where the game is played.

How to update the game

If you improve something in the game:

  1. Change and test snake.html as usual.
  2. Save it again as index.html with "Save As". Geany will ask whether to replace the file — say yes. Close the index.html tab.
  3. On GitHub, in the snake repository: Add file → Upload files, choose the new index.html and click Commit changes. The old file is replaced by the new one.
  4. Wait a minute or two and refresh the game's page.
⚠️ If it doesn't work
  • A 404 page (not found)? Wait a couple more minutes — GitHub Pages doesn't switch on instantly. Check that the file is called exactly index.html, in small letters.
  • A list of files or code text instead of the game? Check that the Pages settings have the main branch and the / (root) folder selected.
  • The game opened but doesn't work? Open the console (F12) — you already know how to read errors!

Bonus: playing on a phone

You can open the link on a phone too, but a phone has no keyboard with arrows. Let's add buttons to the screen! There's a trick here: the onKey function only needs event.key, so a button can call it itself and "pretend" to be a key.

Add this to snake.html under the <p class="help"> hint:

<p>
  <button onclick="onKey({ key: 'ArrowUp' })">Up</button>
</p>
<p>
  <button onclick="onKey({ key: 'ArrowLeft' })">Left</button>
  <button onclick="onKey({ key: ' ' })">Start</button>
  <button onclick="onKey({ key: 'ArrowRight' })">Right</button>
</p>
<p>
  <button onclick="onKey({ key: 'ArrowDown' })">Down</button>
</p>
  • <button> — a button;
  • onclick — what to do when the button is pressed (that's an event too, like keydown);
  • { key: 'ArrowUp' } — we made an object ourselves that looks like a real event. Inside double quotes we write text in single quotes '…', so the quotes don't get mixed up.

And a little CSS in <style>, so the buttons are easy to press with a finger and the field fits on a narrow screen:

    button {
      font-size: 20px;
      width: 110px;
      height: 56px;
      margin: 4px;
    }
    canvas {
      max-width: 90%;
    }

Check on the computer that the buttons work, then update index.html on GitHub and open the link on a phone.
